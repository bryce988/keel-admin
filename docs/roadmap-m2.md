## 0. 前置：先做这三件，再碰模块

七个模块的页面结构高度重合。不先把重合部分收敛掉，就会写出七套各不相同的实现。

- [x] **P1 `ProTable` 列表状态同步到 URL**（M1 遗留）
  - 分页、排序、筛选条件写进 query string，刷新后还原
  - 用 `router.replace` 而不是 `push`：翻十页就往历史里塞十条，返回键会变得没法用
  - 数字型筛选字段必须在 `paramParsers` 里登记（`{ status: Number }`）——
    URL 里的值**永远是字符串**，不转的话 `el-select` 显示空白、树的选中态对不上
  - 多页签必须存 `fullPath` 而不是 `path`，否则切走再切回来筛选条件全丢，前面白做

  **验收**（每条都要真点一遍，类型检查发现不了这些）
  - [x] 改筛选 / 翻页 / 排序，地址栏跟着变；默认值（第 1 页、默认 pageSize）不写进 URL
  - [x] 刷新页面，筛选条件、页码、排序原样回来
  - [x] 切到别的页签再切回来，条件还在
  - [x] 点「重置」不报错，且地址栏参数被清空
  - [x] 树形筛选（部门树）刷新后**选中高亮还在**——这条最容易翻车，验的是 `paramParsers`
  - [x] **改完筛选立刻取数，用的是新值**——见下方「已踩过的坑」

  **已踩过的坑**：`params` 是 prop，页面整体赋值（`query.value = {...}`）后
  要等父组件重新渲染才传得进来。若 `reload()` 不等这一拍，`fetch()` 读到的是**上一次**的
  筛选值——表现为点部门树数据慢一拍，来回点两个部门就完全对调。
  修在 `ProTable.reload()` 里 `await nextTick()`，**不要**让每个页面自己 await：
  七个模块二十几个筛选交互，总有一处会忘，而且这种 bug 不报错，只是数据悄悄错一拍。
- [x] **P2 表单弹窗规范**
  - `FormDialog` 只统一「壳」——打开、深拷贝、校验、提交、loading、错误回填、关闭；
    字段用插槽自由写。schema 驱动放弃了：菜单表单光 type 就有五种形态，
    会长出一堆 `show: (form) => ...` 谓词，变成没人愿意读的小框架
  - 深拷贝再编辑：直接编辑列表行对象的话，没点保存表格就变了，取消也回不去
  - 服务端错误两条回填路径：422 按 `details` 逐字段对号入座；
    409/400 只有一条 message，靠 `errorFields`（业务码 → 字段名）落到输入框
  - 失败时弹窗不关，用户可以直接改
  - 用顶栏「修改密码」做了真接口验证，顺带填掉了那个“将在 M2 实现”的占位
- [ ] **P3 后端写接口的通用件**
  - 唯一性校验（重复时抛 409 + 对应业务码）
  - 删除前的被引用检查（部门有用户、角色有成员、权限点被引用）
  - 批量删除与「返回成功/失败明细」的统一格式（api.md §1.4）

**预计 1.5 天。** 后面七个模块每个能省掉大半天。

## 1. 阶段与顺序

顺序按 **RBAC 三层（定义 → 授权 → 分配）+ 依赖关系** 排，不是随便挑的。

### M2.1 部门 + 岗位

**为什么第一**：它是数据权限的载体，后面每个模块的归属过滤都依赖它；且零依赖。

- [ ] 后端 `depts` CRUD：新建、编辑、删除、树查询
  - 移动部门时**同步刷新所有子孙的 `ancestors`**（database.md §3.2）
  - 上级不能是自己或自己的子孙（400 + `20202`）
  - 有用户或子部门时不可删（409 + `20203`）
- [ ] 后端 `posts` CRUD
- [ ] 前端 部门树表页（第一个树表页，顺手抽成可复用的页型）
- [ ] 前端 岗位列表页

**验收**：移动一个部门后，用该部门主管账号调 `/admin/users`，
可见范围立刻跟着变——说明 `ancestors` 真的刷新了，且全局 Scope 读到了新值。

### M2.2 菜单与权限（**定义**层）

**为什么第二**：RBAC 的定义层，角色授权要勾它；做完立刻能验证动态路由。

- [ ] 后端 `menus` 树查询 / CRUD
  - 权限点被角色引用时不可删，只能停用（409 + `20402`）
  - 上级不能是自己或子节点（400 + `20403`）
- [ ] 前端 菜单树表 + 节点表单
  - 五种 `type` 的表单字段**完全不同**：目录没有 `api_path`，按钮没有 `component`，
    数据(字段)权限只有名称与标识。表单要按 type 动态切换，不要堆成一个大表单
- [ ] 前端 角色×权限审计矩阵（只读）

**验收**：新增一个菜单 → 授权给某角色 → 该角色的用户刷新页面就看到，**全程不发版**。
这条是「不写死菜单」这个设计成立与否的唯一证据。

### M2.3 角色（**授权**层）

依赖 M2.1（数据范围要选部门）、M2.2（权限树）。

- [ ] 后端 `roles` CRUD（内置角色不可改删，403 + `20302`）
- [ ] 后端 `grantPerm` 保存功能权限 → 递增持有者的 `perm_version`
- [ ] 后端 `grantData` 保存数据范围（含 `data_scope=5` 时的 `sys_role_depts`）
- [ ] 后端 字段级权限（见下方待定问题 ②）
- [ ] 后端 角色成员的增删
- [ ] 前端 角色列表 + 权限树勾选 + 数据范围 + 成员管理
  - 权限树的父子联动、继承来的节点置灰不可取消
  - 互斥角色（400 + `20304`）、角色数上限（`20305`）、继承环（`20306`）三个校验

**验收**：给在线用户改授权，该用户**不重新登录**，下一个请求就按新权限判定。

### M2.4 用户（**分配**层）

依赖前三个。当前只有只读列表，这一步补成完整 CRUD。

- [ ] 后端 create / update / delete / status / resetPwd / grantRole
  - 不允许操作超级管理员（403 + `20103`）
  - 停用有归属数据的账号要先交接（400 + `20104`）
- [ ] 后端 import / export（见下方待定问题 ①）
- [ ] 前端 把现有只读页补成完整 CRUD + 角色分配弹窗

**验收**：数据权限五种范围**全部**跑一遍——补上 M1 遗留的「本部门」与「自定义部门集合」两种。

### M2.5 字典 + 参数

**零依赖，可随时插队。** 想换个轻松点的活干就插进来。

- [ ] 后端 字典类型与字典项 CRUD
  - 写入后主动 `DictService::forget()`，否则改了不生效
  - 已被引用的 `value` 不可改（409 + `20502`）
- [ ] 后端 参数按分组查询 / 批量保存
  - `is_secret = 1` 的参数**只写不读**：查询返回掩码，保存时值为掩码则跳过更新
- [ ] 前端 字典主从页（左类型右字典项）
- [ ] 前端 参数分组页（基础/安全/集成/高级四个 tab）

**验收**：改一个字典项的 `tag_type` → 不刷新浏览器，切到别的页面再回来，标签颜色跟着变。

### M2.6 操作日志 + 登录日志

**放最后**：前面五步跑起来才有真实数据可查，否则只能对着空表调界面。

- [ ] 后端 操作日志列表 / 详情 / 导出（时间范围必填，默认最近 7 天）
- [ ] 后端 登录日志列表 / 导出
- [ ] 前端 两个只读列表 + 详情抽屉
  - 详情要展示 `changes` 的字段级 diff（旧值 → 新值），这是日志最有价值的部分

**验收**：前面五个阶段产生的写操作都能查到；换 `manager` 账号看，只能看到本部门的操作记录。

### M2.7 权限矩阵收尾

- [ ] 用 `manager` / `dev01` 各完整跑一遍：越权菜单不可见、直接调接口被拒
- [ ] 把 `scripts/seed.php` 里内置角色的授权按新增的权限点补齐
- [ ] 更新 README 功能一览的状态列与路线图

## 2. 待定：开工前需要拍板的三件事

### ① 导入导出用什么

| 方案 | 优点 | 代价 |
|---|---|---|
| **纯 CSV**（倾向） | 零依赖，内存友好 | 不支持样式与多 sheet |
| PhpSpreadsheet | 功能全，支持模板 | 20MB+ 依赖，且**吃内存**——常驻进程下要格外小心 |

**倾向 CSV**：脚手架不该为了导出背一个重依赖，真需要 Excel 的项目自己加。
无论选哪个，导出都必须走 chunk 分批，不能一次 `get()` 全表（CLAUDE.md 常驻内存红线）。

### ② 字段级权限的界面

`角色 × 对象 × 字段` 是三维的，直接暴露成配置表格没人看得懂。

**倾向简化版**：在角色编辑页给一个多选框，列出**代码里声明的敏感字段清单**
（当前是 `sys:field:user:phone`、`sys:field:user:email`），而不是让人配置任意表的任意字段。
`sys_role_fields` 表结构保持不变，完整版留到有真实需求时再放开。

### ③ 五种页型模板（M3）现在抽还是最后抽

**倾向边做边抽**：M2.1 写第一个树表页时就抽成模板，M2.2 的菜单树直接复用。
等七个模块都写完再回头抽，等于把七份代码重写一遍。
这样 M3 会自然缩水成「补文档 + 补缺的两种页型」。

## 3. 贯穿始终的约束

每个模块开工前重读一遍 CLAUDE.md 的硬性约定，尤其这几条：

- 新增写接口必须在 `config/route.php` 声明 `perm`，**不写就是 403**；写接口还要带 `log`
- 数据权限由模型全局 Scope 注入，**禁止业务代码手写归属过滤**
- 控制器不查库不拼状态码；事务只在 service 层
- 前端不写死颜色、枚举、菜单；列表页统一用 `SearchForm` + `ProTable`
- 接口字段一律 snake_case，与数据库字段名逐字一致
- 表结构改动写进 `server/database/schema.sql`，权限点/字典改动写进 `scripts/seed.php`
