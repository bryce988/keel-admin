# 角色与权限

## 基本模型
- 用户不直接绑定权限，只绑定**角色**；一个人有多个角色时，功能权限取**并集**
- 权限点分四类：**菜单**（能不能进页面）、**按钮**（页面里的操作）、**接口**（服务端校验）、**数据/字段**（如能否看手机号明文）
- 前端隐藏按钮只是界面收敛，真正的拦截在服务端：没有权限直接调接口同样会被拒绝（403）
- 授权变更**立即生效**，被授权的人不需要重新登录

## 怎么给角色授权
在「系统管理 / 角色管理」（/system/role）找到角色，点「分配功能权限」，在权限树里勾选。
需要「分配功能权限」按钮的权限（sys:role:grantPerm）。

权限树的勾选规则和常见的树不一样：
- 勾一个子节点（比如某个按钮），会**自动补上它的上级菜单**——按钮离开菜单没有意义
- 取消一个父节点，会**清掉它下面所有子节点**
- 勾一个父节点**不会**自动全选子节点——想只给「用户管理」的查看权限，不该连删除、重置密码一起给出去

## 超级管理员
- 超级管理员拥有全部权限与全部数据，新加的权限点对超管自动生效
- 超管角色**没有**可配置的授权集合，界面上不显示授权按钮
- 只有超管才能把超管角色授予别人

## 内置角色
超级管理员、部门主管、普通员工等。部门主管默认能管本部门及下属部门的人，普通员工默认只有首页与消息。
「AI 助手」权限（ai:use）默认不授予任何内置角色，需要管理员按角色开启。

## 其他规则
- 互斥角色不能同时授予同一个人
- 一个账号的角色数量有上限（可配置）
